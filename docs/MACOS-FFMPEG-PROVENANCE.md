## Fixed build environment and closure

Use an Apple Silicon GitHub-hosted `macos-15` runner with **Xcode 16.4 (build `16F6`)** selected explicitly at `/Applications/Xcode_16.4.app/Contents/Developer` and its **macOS 15.5 SDK**, and Python **3.12.15** selected by the workflow. The [GitHub runner image inventory](https://github.com/actions/runner-images/blob/main/images/macos/macos-15-arm64-Readme.md) lists the Xcode tools and confirms the arm64 image; [Apple's Xcode 16.4 notes](https://developer.apple.com/documentation/xcode-release-notes/xcode-16_4-release-notes) identify SDK 15.5. Fail if the actual host is x86_64 or the Python/Xcode build/SDK differs. Set `MACOSX_DEPLOYMENT_TARGET=12.3`, `SOURCE_DATE_EPOCH=1789951738`, `LC_ALL=C` and `TZ=UTC`. Compile against the selected SDK using native arm64 clang/clang++, and record the resolved compiler/SDK paths, versions, source hashes, machine identity, runner image version and SHA-256 of compiler/build-tool executables plus `SDKSettings.json` in the build attestation. Those hashes are *observations from the runner*, not invented pre-approval values. Do not copy or redistribute Apple's SDK.

The build source closure is as follows:

1. Verify the checksum and extraction path of **every** archive before executing any source, with a separate isolated prefix and exact `PKG_CONFIG_LIBDIR` containing only files produced from this lock. Disable Meson wrap/subproject downloads. Build pkgconf from its `configure`, bootstrap Ninja from its pinned `configure.py` with native C++, and invoke Meson directly through its pinned `meson.py` and runner Python. Use no mutable Homebrew pkgconf, Meson or Ninja installation.
2. Build **static FreeType** without optional zlib, PNG, bzip2, Brotli or HarfBuzz dependencies; build **static FriBidi**. This avoids an unrecorded compression/graphics library dependency and a circular FreeType/HarfBuzz link.
3. Build **static HarfBuzz** for core complex-script shaping and **enable its FreeType bridge** against the already-pinned static FreeType. FFmpeg 8.1.3 `drawtext` requires that bridge and its installed `hb-ft.h` header. FreeType itself remains built without HarfBuzz, avoiding a circular dependency. Disable optional GLib/GObject, Cairo, ICU, Graphite2, CoreText shaping backend, experimental raster/vector/GPU, fontations/Rust, PNG/zlib, subsetting, tools, docs and tests. Use only the recorded native compiler and Ninja. Verify the installed header and private-prefix static FreeType link; do not resolve an untracked system or downloaded substitute.
4. Build **static libass 0.17.5** against only the pinned FreeType/FriBidi/HarfBuzz libraries. **Enable CoreText as the required macOS system font provider** and disable Fontconfig, libunibreak, Windows DirectWrite, test utilities, optional PNG and NASM assembly. Keep the system-font-provider requirement enabled so the build cannot silently fall back to no font discovery. libass retains its HarfBuzz Khmer shaping; the same pinned HarfBuzz build also supplies FFmpeg's FreeType bridge.
5. Build **static x264** from the exact full VideoLAN commit archive; disable its CLI/OpenCL helpers and do not include any commercial/nonfree linked library. Preserve H.264 encoding via `libx264`, with the resulting GPL licensing handled below.
6. Build **FFmpeg 8.1.3** and `ffprobe` for native arm64 with `--enable-gpl --enable-version3 --enable-static --disable-shared --enable-libass --enable-libharfbuzz --enable-libx264 --disable-autodetect --disable-doc --disable-debug --disable-ffplay`. Never enable `--enable-nonfree`, OpenSSL, libfdk-aac, or any unpinned external codec/filter. Explicitly carry the CoreText/CoreFoundation framework links from libass. Retain the ordinary built-in media demuxers, decoders, AAC codec, local-file protocols, subtitles/ass filters and stream-copy needs instead of blindly disabling everything. Stage two executables, `ffmpeg` and `ffprobe`, and verify there is no dynamic linkage to the private build prefix, `/opt/homebrew`, `/usr/local`, or other unreviewed third-party libraries.

FFmpeg additionally enables **SDK/system zlib** explicitly with `--enable-zlib`, retaining PNG decoding and encoding when automatic dependency detection is disabled. This uses macOS's system `/usr/lib/libz.1.dylib`, with the selected SDK headers; no zlib binary or static source is downloaded or redistributed. The native linkage check rejects any Homebrew, private-prefix or other external zlib. FreeType and HarfBuzz retain their separately disabled optional compression links.

The [libass build's CoreText implementation](https://github.com/libass/libass/blob/0.17.5/meson.build) explicitly supports Mac CoreText and its system-font-provider check; no Fontconfig source is necessary if the resulting real-Mac Khmer font test succeeds. Its upstream 0.17.5 release includes memory-safety repairs to earlier libass versions. This design retains the native Khmer `subtitles`/`ass` shaping requirements without pulling in ICU, Graphite2, Fontconfig, FreeType compression libraries, or an untracked build dependency. If real Khmer testing demonstrates an additional dependency is necessary, revise the lock and corresponding-source list before rebuilding; do not use a silent system fallback.

This does not relicense the original FFmpeg source files, FreeType, FriBidi, HarfBuzz, libass or build tools; retain every actual source license and notices. The relevant primary guidance is [FFmpeg's legal and license checklist](https://ffmpeg.org/legal.html), [FFmpeg source `LICENSE.md`](https://ffmpeg.org/releases/ffmpeg-8.1.3.tar.xz), [libass `COPYING`](https://github.com/libass/libass), and [x264's upstream source](https://code.videolan.org/videolan/x264). The lock identifies license paths to preserve verbatim. The full upstream tarballs preserve additional per-file notices beyond those paths.

Before publishing, obtain independent license/distribution review of static-link compatibility, required attribution, no-warranty and license disclosures, full corresponding source, conveying location, installation information where applicable, patent considerations and any obligations arising from Apple platform linkage. The runtime itself should be a separate immutable GitHub asset with a versioned filename, its own SHA-256 checksum, `ffmpeg` and `ffprobe`, and only the runtime closure actually needed. The existing v0.85.6 runtime ZIP, runtime URL/SHA pin, GitHub Release, package manifest, site/docs representation, `THIRD_PARTY_NOTICES.md` and OTA pointers stay unchanged during this preparation. ## Acceptance before considering a release

The build worker must produce immutable artifact evidence, plus real Apple Silicon verification that `lipo` reports arm64, Mach-O load commands and `vtool` establish an appropriate 12.3 minimum, `otool -L` exposes only allowed Apple system dynamic libraries, both tools report the expected version, and `ffmpeg -buildconf` contains exactly the required GPL/libass/libharfbuzz/libx264 capabilities without nonfree or unpinned options. `ffmpeg -h filter=ass` must expose `shaping` and `complex`, and `ffmpeg -encoders` must contain `libx264`. Render mixed Khmer/English glyph clusters with real fonts, verify MP4 H.264/AAC audio/video and `ffprobe`, exercise Studio's full native caption-preview and captioned-video-export paths, and run setup-time checksum-failure, interruption, upgrade, rollback and user-state preservation cases. Record the exact test media ownership and avoid incorporating user projects into any released artifact.

**Public impact: required upon a later approved release** because a managed native binary, GPL/source publication obligations, compatibility evidence and user-install/update path would change. This preparation changes only the two new source-lock/provenance files. A separate license review, reviewed build, source/recovery assets, native acceptance, revised runtime pin, product evidence/HQ intake and Distribution sync approval are prerequisites to advertising availability; none are implied by the new lock.
